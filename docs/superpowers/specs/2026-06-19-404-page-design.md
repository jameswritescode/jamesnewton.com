# 404 Page with a Frowning Matrix — Design Spec

**Date:** 2026-06-19
**Status:** Approved (pending written review)
**Branch context:** `phoenix-migration`

## Overview

Replace the bare white "Not Found" text with a real 404 page that uses the normal
site layout (header + ripple-canvas background), shows a friendly 404 message and
a link home, and — for fun — draws a **frowning face into the background dot
matrix**. The frown is monochrome (brighter versions of the existing dots) and
gently "breathes" via a slow sine, so it subtly sulks behind the message.

## Current behaviour (reference)

- `config :newton, NewtonWeb.Endpoint, render_errors: [formats: [...], layout: false]`
  → errors render with no layout. `NewtonWeb.ErrorHTML.render/2` returns the plain
  status text ("Not Found"), so a bad URL is a white page with bare text.
- The "matrix" is the `RippleCanvas` hook (`assets/js/hooks/ripple_canvas.js`): a
  full-screen `<canvas id="rippleCanvas" phx-hook="RippleCanvas">` in
  `root.html.heex`, drawing a grid of dots (spacing 20px) with animated ripples.
  It already honours `prefers-reduced-motion` (static dots, no animation) and
  mounts on dead controller views (the public site is controller-rendered).
- Two distinct 404 paths reach the error renderer with **different conn state**:
  - **`Phoenix.Router.NoRouteError`** (e.g. `/anything`): raised *before* any
    pipeline runs, so `@csp_nonce` is **not** assigned and no CSP header is set.
  - **`Ecto.NoResultsError`** (e.g. `/posts/bad-slug`): the `:browser` pipeline
    ran first, so `@csp_nonce` **is** assigned and a CSP header is present. Phoenix
    maps both exceptions to HTTP 404 via the `Plug.Exception` protocol.
- Phoenix supports `render_errors: [layout: ..., root_layout: ...]`
  (`deps/phoenix/lib/phoenix/endpoint/render_errors.ex:116-117`).

## Section 1 — Render errors inside the normal layout

- **Config (`config/config.exs`):** change `render_errors` to
  ```elixir
  render_errors: [
    formats: [html: NewtonWeb.ErrorHTML, json: NewtonWeb.ErrorJSON],
    root_layout: {NewtonWeb.Layouts, :root},
    layout: false
  ]
  ```
  Using `root_layout` (not `layout`) wraps the error template in
  `root.html.heex` — which carries the ripple canvas, fonts, theme script, and
  `app.js` — without imposing the app's inner layout (the 404 template provides
  its own header/main, mirroring how public pages compose).
- **Root layout nonce safety (`root.html.heex`):** change
  `<script nonce={@csp_nonce}>` to `<script nonce={assigns[:csp_nonce]}>`. On the
  `NoRouteError` path `csp_nonce` is unassigned; `@csp_nonce` would raise a
  `KeyError`, whereas `assigns[:csp_nonce]` yields `nil` (HEEx then omits the
  attribute). That path also has no CSP header, so the nonce-free inline theme
  script still runs. The `Ecto.NoResultsError` path keeps its real nonce.

## Section 2 — The 404 template

- **`NewtonWeb.ErrorHTML`:** uncomment/enable `embed_templates "error_html/*"` and
  add `lib/newton_web/controllers/error_html/404.html.heex`. Keep the existing
  `render/2` clause as the fallback for other statuses (500, etc.) — they render
  their plain status text inside the root layout, which is acceptable.
- **`404.html.heex` content:** compose the normal chrome the way public pages do —
  `<Layouts.site_header />` then a `<main id="main">` containing a `.post`-styled
  block:
  - a large "404",
  - a short, on-brand line (copy: **"This page wandered off."**),
  - a link **"← Back home"** to `~p"/"`.
  - a hidden frown marker: `<div data-frown hidden></div>` (see Section 3).
- The template must not depend on assigns that aren't present in an error render
  (no `@flash`, no `@current_scope`); use only static content, `~p` verified
  routes, and `Layouts.site_header/1`.

## Section 3 — Frown in the matrix (`RippleCanvas`)

- **Activation:** in `mounted()`, the hook checks
  `document.querySelector("[data-frown]")`. If present, it enters **frown mode**.
  (Frown mode only needs to work on a fresh load of a 404 — the common case.
  Swup-navigating *into* a 404 without a canvas remount is out of scope.)
- **Geometry — pure helper `frownPoints(width, height)`:** returns sampled feature
  points in canvas pixels for a sad face centred on the viewport:
  - `eyes`: two points at `(cx ± eyeDx, cy − eyeDy)`.
  - `mouth`: `N` points along an **upward-opening arc** (a frown) below centre —
    i.e. the arc dips at the sides and rises in the middle.
  - The face is scaled to the viewport (≈ `0.4 * min(width, height)`) and centred
    (`cx = width/2`), with `cy` chosen so the face reads above/around the message
    (tuned in implementation). Pure function → unit-testable.
- **Rendering:** the hook recomputes `frownPoints` on load and on resize. In the
  per-dot draw loops (both the animated ripple branch and the static
  reduced-motion branch), each dot gets an additional **frown boost**: the gaussian
  of its distance to the nearest feature point, within an influence radius (~1.5×
  dot spacing), times a breathing amplitude. The dot's opacity becomes
  `min(1, dotOpacity + (FROWN_PEAK − base) * boost)`, drawn in the existing dot
  colour (`rgba(var(--dot), …)`) — **monochrome**, no accent.
- **Breathing:** amplitude = sine over a slow period (≈3.5s) mapped to a gentle
  range (e.g. 0.5–1.0 of `FROWN_PEAK`). Under `prefers-reduced-motion`, the frown
  renders **statically** at a fixed amplitude (no breathe, no ripples) — matching
  the hook's existing reduced-motion handling, which calls a one-shot static
  render.
- **Konami bloom mode** is unaffected (frown boost applies to the normal/static
  branches; the rainbow bloom branch is left as-is).

## Section 4 — Layout / visual integration

- The canvas is fixed, full-screen, behind all content. The frown is therefore
  *behind* the message. Position the frown centre and the `<main>` content so they
  complement rather than collide — e.g. frown centred slightly high with the 404
  text sitting in the lower-middle, or the text small enough to nest within the
  face. Exact placement and the frown scale/`FROWN_PEAK` are tuned visually with
  Playwright screenshots (light + dark) during implementation.

## Error handling / edge cases

- **Unknown route vs missing record:** both render the same 404 template; the only
  difference is nonce presence, handled in Section 1.
- **Reduced motion:** static frown, no breathing, no ripples (Section 3).
- **JS disabled / canvas unsupported:** no frown, but the 404 message + link still
  render normally (progressive enhancement; the canvas is decorative and
  `aria-hidden`).
- **Other error statuses (500, etc.):** render their plain status text inside the
  root layout. No frown marker, so no frown. Acceptable; styling them is out of
  scope.
- **Dev `debug_errors: true`:** Phoenix shows its interactive debugger instead of
  this page; previewing the real 404 in dev requires temporarily setting
  `debug_errors: false`. Documented, not changed by this work.

## Testing approach

- **vitest:** `frownPoints(width, height)` — assert two eye points placed
  symmetrically about the horizontal centre and above `cy`, and a mouth sampled
  into points whose middle sits **lower** on screen than its ends (the frown
  curve), scaling with the viewport. (The canvas drawing itself is covered by the
  Playwright pass.)
- **Elixir (`error_html` / controller test):** with the error view rendered,
  `get(conn, "/nonexistent")` returns status 404 and the body contains the 404
  message and the home link; `get(conn, "/posts/bad-slug")` likewise returns 404.
  (Tests run with `debug_errors` off, as ConnCase does.)
- **Playwright (manual/scripted, PORT=4001):** visit `/nonexistent` and
  `/posts/bad-slug`; assert the styled 404 (heading + "Back home" link) and the
  `[data-frown]` marker are present and the canvas is drawn; screenshot light +
  dark to confirm the frown reads.

## Unit breakdown

- `config/config.exs` — `render_errors` root layout.
- `lib/newton_web/components/layouts/root.html.heex` — nonce-safe script.
- `lib/newton_web/controllers/error_html.ex` — `embed_templates`.
- `lib/newton_web/controllers/error_html/404.html.heex` — the page (new).
- `assets/js/hooks/ripple_canvas.js` — `frownPoints/2` helper + frown-mode boost.
- `assets/css/site.css` — any 404-specific layout/spacing (reusing `.post`).

## Out of scope (future follow-ups)

- Styling non-404 error pages (500, 503, …) beyond the inherited layout.
- A frown when Swup-navigating into a 404 without a fresh load.
- Accent-coloured or interactive frown; other error-page illustrations.
